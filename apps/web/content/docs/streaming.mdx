Progressively render UI as AI generates it.

## SpecStream Format

json-render uses **SpecStream**, a JSONL-based streaming format where each line is a JSON patch operation that progressively builds your spec:

```json
{"op":"add","path":"/root","value":"root"}
{"op":"add","path":"/elements/root","value":{"type":"Card","props":{"title":"Dashboard"},"children":["metric-1","metric-2"]}}
{"op":"add","path":"/elements/metric-1","value":{"type":"Metric","props":{"label":"Revenue"}}}
{"op":"add","path":"/elements/metric-2","value":{"type":"Metric","props":{"label":"Users"}}}
```

## Patch Operations (RFC 6902)

SpecStream uses [RFC 6902 JSON Patch](https://datatracker.ietf.org/doc/html/rfc6902) operations:

- `add` — Add a value at a path (creates or replaces for objects, inserts for arrays)
- `remove` — Remove the value at a path
- `replace` — Replace an existing value at a path
- `move` — Move a value from one path to another (requires `from`)
- `copy` — Copy a value from one path to another (requires `from`)
- `test` — Assert that a value at a path equals the given value

## Path Format

Paths follow JSON Pointer (RFC 6901) into the spec object:

```bash
/root                       -> Root element key (string)
/elements/card-1            -> Element with key "card-1"
/elements/card-1/props      -> Props of card-1
/elements/card-1/children   -> Children of card-1
```

## Server-Side Setup

Ensure your API route streams properly:

```typescript
import { streamText } from 'ai';
import { catalog } from '@/lib/catalog';

export async function POST(req: Request) {
  const { prompt } = await req.json();
  
  const result = streamText({
    model: 'anthropic/claude-haiku-4.5',
    system: catalog.prompt(),
    prompt,
  });

  // Return as a streaming response
  return result.toTextStreamResponse();
}
```

## Low-Level SpecStream API

For custom or framework-agnostic streaming implementations, use the SpecStream compiler from `@json-render/core` directly:

```typescript
import { createSpecStreamCompiler } from '@json-render/core';

// Create a compiler for your spec type
const compiler = createSpecStreamCompiler<MySpec>();
const decoder = new TextDecoder();

// Process streaming chunks from AI
async function processStream(reader: ReadableStreamDefaultReader<Uint8Array>) {
  while (true) {
    const { done, value } = await reader.read();
    if (done) break;

    // Decode the Uint8Array chunk to a string
    const chunk = decoder.decode(value, { stream: true });
    const { result, newPatches } = compiler.push(chunk);
    
    if (newPatches.length > 0) {
      // Update UI with partial result
      setSpec(result);
    }
  }
  
  // Get final compiled result
  return compiler.getResult();
}
```

### One-Shot Compilation

For non-streaming scenarios, compile entire SpecStream at once:

```typescript
import { compileSpecStream } from '@json-render/core';

const jsonl = `{"op":"add","path":"/root","value":"card-1"}
{"op":"add","path":"/elements/card-1","value":{"type":"Card","props":{"title":"Hello"},"children":[]}}`;

const spec = compileSpecStream<Spec>(jsonl);
// { root: "card-1", elements: { "card-1": { type: "Card", props: { title: "Hello" }, children: [] } } }
```

## Usage with React

`@json-render/react` provides the `useUIStream` hook, which wraps the low-level compiler in a React-friendly API with state management, error handling, and abort support.

### useUIStream Hook

```tsx
import { useUIStream } from '@json-render/react';

function App() {
  const {
    spec,          // Current UI spec state
    isStreaming,   // True while streaming
    error,         // Any error that occurred
    send,          // Function to start generation
    clear,         // Function to reset spec and error
  } = useUIStream({
    api: '/api/generate',
    onComplete: (spec) => {},  // Optional: called when streaming completes
    onError: (error) => {},    // Optional: called when an error occurs
  });
}
```

### Progressive Rendering

The Renderer automatically updates as the spec changes:

```tsx
function App() {
  const { spec, isStreaming } = useUIStream({ api: '/api/generate' });

  return (
    <div>
      {isStreaming && <LoadingIndicator />}
      <Renderer spec={spec} registry={registry} loading={isStreaming} />
    </div>
  );
}
```

### Aborting Streams

Calling `send` again automatically aborts the previous request. Use `clear` to reset the spec and error state:

```tsx
function App() {
  const { isStreaming, send, clear } = useUIStream({
    api: '/api/generate',
  });

  return (
    <div>
      <button onClick={() => send('Create dashboard')}>
        Generate
      </button>
      <button onClick={clear}>Reset</button>
    </div>
  );
}
```

See the [@json-render/react API reference](/docs/api/react) for full `useUIStream` documentation.

## Compact streaming

### Schema-enforced generation

`createCompactGeneration(catalog.data, { strict: true })` derives a strict wire schema and matching decoder from the component Zod schemas. Use this profile with OpenAI strict structured outputs: every object is closed and every field is required.

```ts
import { createCompactGeneration } from "@json-render/core";

const generation = createCompactGeneration(catalog.data, { strict: true });
const request = {
  messages: [
    { role: "system", content: generation.prompt },
    { role: "user", content: userPrompt },
  ],
  stream: true,
  response_format: {
    type: "json_schema",
    json_schema: {
      name: "compact_ui",
      strict: true,
      schema: generation.jsonSchema,
    },
  },
};

// textStream contains decoded model text, not the provider's SSE envelope.
const jsonl = textStream.pipeThrough(generation.createTransform());
```

Use the plain user request here. `buildUserPrompt()` appends instructions for stock JSONL output and must not be combined with this format. Configure the model and provider in the application. On OpenRouter, require parameter support in routing so an endpoint cannot silently ignore structured outputs. Unsupported schema features must fail; do not remove constraints to make a provider accept a request.

The decoded document contains a nested `root` component and optional `state`. Components contain `type`, `props`, and applicable `children`, `slots`, `visible`, `repeat`, `on`, and `watch` fields. Children and named slots contain component objects, never IDs or references. Code assigns IDs and connects children, preventing duplicate IDs, missing references and cycles. Validated components become ordinary JSONL patches as their props arrive, before the entire document finishes. Existing streaming adapters consume this JSONL without additional options.

The strict profile changes only the model's wire format:

- Optional fields use `null` for absence and `{ "value": ... }` for presence. `{ "value": null }` preserves an explicit null.
- Records use `{ "entries": [{ "key": "name", "value": ... }] }`. Duplicate keys are rejected.
- Unions whose encoded alternatives overlap use a `case` discriminator and a `value`.
- Nodes include all metadata fields, `children`, and `slots`. Unused child lists and named slots are empty arrays.

Use the returned prompt and schema together; the compiler reverses this encoding before validating or publishing a component. The strict profile rejects unsupported catalog schema types rather than dropping constraints. Tuples, intersections, defaults, and transforms require the native profile or a different catalog schema. Custom refinements still run in the decoder; providers cannot enforce JavaScript callbacks.

Without `{ strict: true }`, `createCompactGeneration(catalog.data)` retains the native nested JSON format, including omitted fields and ordinary record objects. That schema is for providers supporting its full JSON Schema contract; it is not compatible with OpenAI strict mode. Do not send the native schema with `strict: true` or disable strictness as an automatic fallback.

For direct spec consumption, `createCompiler()` provides `push(text)` and `getResult()`. Call `getResult()` at completion to reject truncated or invalid documents. The decoder validates values independently of provider enforcement and rejects transformations or stripped fields. It preserves state expressions and interactions, but cannot guarantee factual accuracy, valid application actions, or visual design quality. This API generates complete flat UI specs; subsequent edits can use the existing JSONL protocol. Generated IDs follow tree positions and are not stable across newly generated layouts.

Partial snapshots are provisional. `getResult()` and transform completion also run the shared structural validator, including repeat-state checks. Propagate completion errors instead of treating a partial preview as a successful generation.
